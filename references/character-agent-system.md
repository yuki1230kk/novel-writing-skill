# 角色分类与角色子 Agent 系统

## 新角色分类

初始化时向作者简要说明以下四类及“逐个确认／允许暂定”偏好；推荐允许暂定，之后不重复讲解。角色分类如下：

- S 类：核心主角、核心感情角色或贯穿全书的绝对核心，维护独立角色档案，关键场景按需调用其 Agent。
- A 类：长期主要配角、长期反派、导师或重要同伴，参与相关剧情时调用独立角色 Agent。
- B 类：只在一个剧情段、副本或案件中承担重要选择的角色，在所属剧情段内调用独立角色 Agent。
- C 类：一次性功能配角、普通龙套或背景人物，不建立独立角色 Agent。

作者说“主要配角”“一次性反派”等已足以判断时直接映射，无需追问字母。无名环境路人不分类。允许暂定时，普通功能角色暂列 C，剧情段重要角色暂列 B，随草稿告知；暂定分类写入草稿资料，不自动污染正式角色卡。新增核心主角、长期感情角色、主要反派的定位或重大升降级尚不明确时才询问。

逐个确认模式下遵守作者偏好，集中询问本次需要确认的角色，继续不依赖它们的工作。S、A、B 各自维护独立视角；是否实际创建 Agent由以下调度决定，不能因已有姓名或出场就自动调用。

## 统一调用调度

本节统一规定角色 Agent 调用次数；对白、战斗和情感文件中的咨询要求合并执行，不另加轮次。

- 普通日常、过场和功能性交流，主 Agent使用有效角色档案与已有咨询结论。
- 新的重要选择、关键战斗、告白、谈判或反转，分别咨询需要新判断的角色；同章同角色的战斗、对白、情感问题合为一次任务，可并行询问不同角色。
- 成稿后仅在出现具体人物失真或重大未决选择时，对受影响角色追加一次针对性复核。无疑点不为完成流程重复询问。
- 角色负责“我会如何行动与表达”，独立读者负责“文字读起来是否自然”。角色不再做全章语言清理，读者不接管角色动机判断。
- 每次输出只回答本次变化、判断依据、自然行动与表达边界，避免复述完整角色卡或逐题长答。复核后仍有分歧，由主 Agent依照授权整合或列出新决策，不无限循环。

## 模型与上下文策略

在支持模型选择的 Codex 环境中，角色 Agent 默认使用 gpt-5.6-terra。S、A 类通常使用 medium；反应相对简单的 B 类可使用 low。Terra 不可用时，选择当前环境中兼顾能力和成本的模型。

创建角色 Agent 时优先使用 fork_turns="none"，不要复制完整会话。主 Agent 把经过筛选的角色上下文直接写入任务：

- L0：本次场景、询问目标、正式状态版本、草稿分支与禁止越权范围。
- L1：角色身份、能力、伤势、资源、关系和当前必须遵守的规则。
- L2：角色亲历的当前场景、相邻关键原文和直接相关对白。
- L3：角色此前经历、长期欲望、误解、秘密、承诺和关系演变。

其他人物秘密、作者层真相、角色尚未经历的未来大纲与废案必须留在该角色的 L4，不得发送。不能为了省 token 只给失真的一句话摘要。

## 正式版本与草稿分支

角色 Agent 不能把未确认草稿永久记作正式经历。每次调用必须标记：

- formal_version：角色正式状态依据到哪一章或哪次正式更新。
- draft_branch：当前未确认草稿分支；没有草稿假定时写 none。
- pending_assumptions：该分支中角色暂时经历的事件。

维护规则：

1. 正式 Agent 只基于正式状态，不接收未确认草稿。
2. 续写未确认草稿时，为该分支创建或复用分支 Agent，并发送正式版本和该分支全部相关待确认变化。
3. 相同版本与分支可直接复用；同一情节路径的正常推进可发送带来源的确认增量、基准版本和新版本后复用，不要求每章重建。
4. 草稿被删除、回退或改成不兼容方案时，废弃对应分支 Agent；不得把它继续用于新分支。
5. 草稿原样正式采用时记录已确认增量，下次调用时告知哪些假定成为正式事实、哪些后续假定仍未确认。若采用版本删除了角色已接收的经历、改变关键动机或切换不兼容分支，则旧 Agent失效，下次重建。不要依赖旧 Agent自称已忘记废稿。正式化动作本身不调用、重建或通知 Agent。

环境不支持持久 Agent 时，每次按上述版本重新创建，反而更安全。需要时使用 assets/project-state-templates/character-agent-snapshot.md 保存可审计的状态摘要，不保存隐藏思维过程。

## 首次建立

给角色 Agent 明确且单一的身份任务：“从某角色的立场理解故事并判断其自然反应，不替作者迎合大纲。”

角色 Agent 首次工作前应获得：

- 角色分类、角色卡与稳定外貌。
- 性格、语言习惯、价值观和行为边界。
- 出身、创伤、秘密、长期目标。
- 能力、装备、伤势和资源。
- 与其他人物的关系。
- 当前掌握、误判与完全不知道的信息。
- 带章节出处的长期经历摘要，以及直接影响本场选择的关键经历原文。

已有可靠角色摘要时不每章重新检索全部出场。具体信息缺失、冲突或需要判断声音与情感时，再定向读取关键场景原文；材料足以支持本次选择时停止扩展。

## 询问格式

规划重要场景时分别询问每个相关角色：

1. 你此刻最想得到什么？
2. 你最怕发生什么？
3. 你知道、误解和隐瞒什么？
4. 若无人强迫，你下一步会做什么？
5. 你会怎样看待在场其他人？
6. 哪种安排会违背你的性格？
7. 你会装成什么态度、回避什么、最容易被哪句话刺中，哪些表达绝不会使用？
8. 你的身体状态、能力和资源会怎样限制选择？

战斗时追加：你会优先攻击、保护、逃跑还是拖延？什么变化会迫使你改变策略？

情感场景追加：你希望对方看见什么，又最怕对方看见什么？你会用什么动作或回避掩盖真实反应？

不必机械要求 Agent 每次逐题长答。简单场景可要求紧凑回答，但不能遗漏影响选择的关键项。规划阶段不要求 Agent 提供成组的“关键台词”或完整对话，避免主 Agent 直接拼接金句。

## 对白规划与成稿复核分离

角色 Agent 在对白规划阶段只提供：交流目标、不能直说的内容、回避点、情绪触发点、伪装态度、说漏嘴条件、关系距离和措辞边界。

主 Agent 写出完整对话后，按统一调用调度判断是否存在需要复核的具体疑点；谈判或感情场景不自动追加调用。需要时提供相关片段，要求该角色：

- 只审查自己的台词与动作。
- 指出哪句不自然、过度完整、过度聪明或泄露信息。
- 给出最小修改方向或替换句，不重写其他人的台词。
- 检查自己的每句是否真实回应上一句话或现场动作。

普通日常和功能性短对话可由主 Agent 依据正式对白档案自行完成，不必重复调用所有角色 Agent。

## 角色输出内部一致性检查

主 Agent 在采用角色建议前逐项核对：

- 建议行动是否违反该角色刚声明的底线。
- 成稿台词是否泄露角色决定隐瞒或根本不知道的信息。
- 台词、动作和策略是否服务于同一个当前目标，又是否真实回应上一轮交流。
- 是否擅自新增能力效果、道具、关系、暗号或共同经历。
- 是否把作者层真相当成角色推断。
- 是否出现“规划说不会做，成稿却立刻做了”的自相矛盾。

发现冲突时按正式资料和作者授权修正；无法判断时使用本章允许的针对性复核，仍涉及未授权的重要故事选择时向作者列出问题。不得挑最方便推进剧情的答案。

## 主 Agent 整合

不同角色 Agent 的意见可以互相矛盾，主 Agent 应利用矛盾生成剧情，而不是要求角色改口配合预定结果。

主 Agent 负责兼顾作者确认方向、商业节奏与外部事件，核对角色建议的版本和信息权限，并完成最终大纲、场景与正文草稿。不得把角色 Agent 当成投票系统，也不得直接拼接各 Agent 输出。

## 并发与降级

优先调用当前场景最重要的 S、A、B 类角色。并发槽位不足时分批询问并保存版本化结论；不得为了省事让一个 Agent 同时扮演多个重要角色。

若环境无法创建子 Agent，主 Agent 必须依据相同分类和版本规则，在内部逐个建立角色视角卡再整合；不得跳过角色动机与知识边界检查。
